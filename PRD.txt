PRD – Dental Laboratory Management System
Product Requirements Document
1. Project Overview
Build a complete, professional Dental Laboratory Management System that manages all laboratory operations in one centralized application.
The system should help the laboratory owner manage:
- Doctors and their accounts.
- Patients and dental cases.
- Products and inventory.
- Laboratory technicians and their commissions.
- Successful and failed dental restorations.
- Expenses, losses, and profits.
- Invoices and PDF reports.
- Monthly and yearly financial performance.
The system must be easy to use, fast, reliable, and fully customizable.
Language: Arabic (Right-to-Left interface).
Currency: Egyptian Pound (EGP).
Platform: Desktop-first, responsive web application.
Data: Persistent database with automatic saving and backup options.

2. Main Dashboard
Create a professional dashboard displaying:
1. Total monthly revenue.
2. Total yearly revenue.
3. Total monthly expenses.
4. Total yearly expenses.
5. Net monthly profit.
6. Net yearly profit.
7. Total number of cases.
8. Number of completed cases.
9. Number of pending cases.
10. Number of failed cases.
11. Total outstanding doctor payments.
12. Total inventory value.
13. Total technician commissions.
Include interactive charts:
- Monthly revenue chart.
- Yearly revenue comparison.
- Expenses versus revenue.
- Successful versus failed cases.
- Most frequently requested products.
- Revenue generated by each doctor.
- Technician performance and commissions.
Allow filtering by date, doctor, technician, and product.

3. Doctors Management
Create a complete Doctors Database.
Each doctor should have:
- Doctor ID.
- Doctor name.
- Phone number.
- Clinic name.
- Address.
- Notes.
- Total orders.
- Total invoices.
- Total payments.
- Remaining balance.
- Total failed cases.
Features:
- Add new doctors.
- Edit doctor information.
- Delete or archive doctors.
- Search doctors by name or phone.
- View each doctor's complete transaction history.
- View all cases associated with a specific doctor.
- View unpaid and partially paid invoices.
- Generate a statement of account for each doctor.

4. Products and Price Management
Create a Products Management section.
The owner must be able to add unlimited products.
Each product should contain:
- Product ID.
- Product name.
- Product category.
- Description.
- Purchase cost.
- Selling price.
- Available quantity.
- Minimum stock alert.
- Unit of measurement.
- Supplier (optional).
Features:
- Add products.
- Edit product names.
- Change prices and costs.
- Change product categories.
- Add or remove stock.
- Track stock movements.
- View product history.
- Automatically update inventory after every transaction.
- Alert the owner when a product reaches its minimum stock level.

5. Dental Cases Management
This is one of the most important modules.
Create a complete system for registering and tracking every dental case.
Each case must include:
- Unique Case Number.
- Invoice Number.
- Date received.
- Delivery date.
- Doctor name.
- Patient name.
- Product / Restoration type.
- Tooth number(s).
- Quantity.
- Unit price.
- Discount.
- Total price.
- Assigned technician.
- Case status.
- Notes.
- Failure status.
Case statuses:
- New.
- In Progress.
- Waiting for Doctor.
- Completed.
- Delivered.
- Failed.
- Rework.
Features:
- Register new cases.
- Edit existing cases.
- Search by patient, doctor, case number, or invoice number.
- Filter by date, technician, product, and status.
- Track delivery deadlines.
- View the complete history of every case.
- Allow multiple products in one invoice.
- Allow multiple technicians to work on a case when necessary.

6. Failed Cases and Loss Management
Create a dedicated Failed Cases Management module.
Every failed restoration must be recorded separately.
Required information:
- Case number.
- Doctor name.
- Patient name.
- Failed product.
- Assigned technician.
- Failure date.
- Failure reason.
- Material cost.
- Technician commission (if applicable).
- Additional expenses.
- Total financial loss.
- Whether the case was remade for free or charged again.
Failure reasons should be customizable.
The system must automatically calculate:
- Total number of failed cases.
- Failure percentage.
- Total material losses.
- Total financial losses.
- Losses per technician.
- Losses per product.
- Monthly and yearly failure statistics.
IMPORTANT:
Failed cases must not be counted as successful revenue when they are remade for free. The system must distinguish between original orders, free remakes, and newly charged orders to avoid double-counting revenue.

7. Technicians and Commission Management
Create a dedicated module for the laboratory's three technicians.
The system should support adding, editing, or removing technicians in the future.
Each technician profile must contain:
- Technician ID.
- Name.
- Phone number.
- Commission percentage.
- Commission calculation method.
- Total assigned cases.
- Completed cases.
- Failed cases.
- Total commission earned.
- Outstanding commission.
- Paid commission.
The owner must be able to:
- Change technician names.
- Change commission percentages at any time.
- Assign cases to technicians.
- View individual technician performance.
- Calculate commissions automatically.
- View commissions by month and year.
- Record commission payments.
- Print technician commission statements.
Commission calculation rules:
Allow the owner to choose whether commissions are calculated based on:
1. Percentage of the selling price.
2. Percentage of the product's net profit.
3. Fixed amount per product.
4. Custom commission per case.
Allow different commission percentages for different products and technicians.
IMPORTANT: Save the commission rate used when each case is registered, so changing a technician's future commission percentage does not modify historical calculations.

8. Inventory and Stock Management
Create a complete inventory management system.
The system must automatically deduct products or materials from stock when they are used in a case.
Features:
- Initial stock registration.
- Add new stock.
- Deduct used quantities.
- Manual stock adjustments.
- Track damaged or wasted materials.
- Track returned materials.
- Stock movement history.
- Current stock balance.
- Low-stock notifications.
- Inventory valuation.
Each stock movement must record:
- Product name.
- Movement type (IN / OUT / ADJUSTMENT / WASTE).
- Quantity.
- Date.
- Related case number (if applicable).
- Notes.
The owner must be able to manually add stock whenever new products arrive.
IMPORTANT:
Never allow stock quantities to change without recording the movement history. Prevent accidental double deductions when editing cases.

Invoice information:

- Invoice number.

- Case number.
- Product description.
- Quantity.
- Unit price.
- Discount.

- Total amount.

- Remaining balance.
Features:
- Generate PDF invoices.
- Download PDF invoices.
- Print invoices.
- Share invoices.
- Generate monthly doctor statements.
- Generate account statements.
- Record partial and full payments.
- Automatically update outstanding balances.
- Support multiple cases and products in one invoice.
Invoice design must be modern, professional, clean, and suitable for a dental laboratory.
Arabic text must display correctly in generated PDF files.

- Total monthly income.
- Total yearly income.

- Total yearly expenses.

13. Data Saving, Security, and Backup
This is a critical requirement.
The system must:
- Automatically save all changes.
- Use a persistent database.
- Never lose data after closing or refreshing the application.
- Support manual data backup.
- Support automatic scheduled backups.
- Allow restoring previous backups.
- Include user authentication.
- Support owner and employee permissions.
- Keep a history of important edits and financial transactions.
- Prevent unauthorized deletion of important records.
Use a reliable database such as PostgreSQL or an equivalent production-ready database.
Do not use temporary browser storage as the primary database.

15. Important Business Logic
The system must follow these rules:
1. Every case must have a unique identification number.
2. Every invoice must have a unique invoice number.
3. Every case must be linked to a doctor.
4. Every case must have an assigned technician or technicians.
5. Stock must be deducted automatically based on configured material usage.
6. Free remake cases must not generate additional revenue.
7. Historical invoices and commission rates must remain unchanged when prices or percentages are edited.
8. Partial payments must update the remaining balance automatically.
9. Failed cases must be included in loss reports.
10. Every financial transaction must be traceable.
11. Editing or canceling a case must create the appropriate inventory and financial adjustments.
12. All dashboard statistics must be calculated from the actual database records.

16. Final Development Requirements
Before development, provide:
- Complete system architecture.
- Database schema and relationships.
- User workflows.
- All application pages.
- Financial calculation formulas.
- Inventory calculation logic.
- Technician commission logic.
Then develop the complete working application.
Do not create just a static UI or a visual prototype.
All buttons, forms, tables, calculations, filters, exports, invoice generation, and database operations must work correctly.
Use realistic sample data for initial testing, but make it possible to remove all demo data before real use.
The final product must be a fully functional Dental Laboratory Management System ready for real-world daily use.
